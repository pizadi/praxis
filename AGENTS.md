# AGENTS.md

FastAPI + React + PostgreSQL clinic management system (rewritten from a legacy Django app; the legacy Django sources are gone from the repo — `old_database/` (local-only, a real production snapshot) remains as reference material only — never import from it in app code). Persian (RTL) UI, Jalali calendar display, permission-based access control.

**Branches**: `main` carries the roles/permissions system; `feature/questionnaires` is stacked on it and adds questionnaire templates/responses; `dev` is the integration branch (v1.3 work lands here first). The questionnaire sections below describe the feature-branch state.

## Commands

Python venv is at the **repo root** (`.venv`), not in `backend/` — from `backend/` use `../.venv/bin/...`.

```bash
# backend tests (run from backend/ — pyproject.toml lives there)
cd backend && DATABASE_URL="sqlite+aiosqlite:///data/clinic-dev.db" ../.venv/bin/python -m pytest tests -q
# single test
../.venv/bin/python -m pytest tests/test_patients.py::test_patient_crud -q

# lint + typecheck (ruff/mypy config in backend/pyproject.toml; run ruff from repo root)
.venv/bin/ruff check backend/app backend/tests scripts
(cd backend && ../.venv/bin/mypy app)

# frontend (run from frontend/)
npm run lint        # eslint, zero warnings allowed
npm run build       # tsc -b && vite build

# deploy to the running compose stack — snapshot the DB FIRST (see below)
docker compose up -d --build api web

# DB snapshot before migrations/destructive ops (pg_dump via docker exec / sqlite copy)
.venv/bin/python scripts/snapshot_db.py --label pre-1.3.0-deploy   # PG (needs the db container up)
.venv/bin/python scripts/snapshot_db.py --sqlite-path backend/data/clinic-dev.db

# full DB reset incl. users (dry run default; admin re-bootstrapped from BOOTSTRAP_ADMIN_*)
.venv/bin/python scripts/purge_db.py            # prints the plan
.venv/bin/python scripts/purge_db.py --yes      # snapshot taken automatically first
```

Verify order: ruff → mypy → pytest → (if frontend touched) tsc/eslint/build.

## Testing quirks

- `backend/tests/conftest.py` sets `DATABASE_URL`/`UPLOAD_DIR`/`SECRET_KEY` env vars **at module import time, before any `app.*` import** — pydantic-settings caches at first import, so env vars must be set before `app.main` is imported anywhere.
- Tests default to SQLite (via aiosqlite) but must also pass on PostgreSQL. For a real-PG run: `docker run -d --name pg-t --network host -e POSTGRES_USER=t -e POSTGRES_PASSWORD=t -e POSTGRES_DB=t postgres:16-alpine`, then `alembic -c alembic.ini upgrade head` and pytest with `DATABASE_URL=postgresql+asyncpg://t:t@localhost:5432/t`.
- Tests build tables via `Base.metadata.create_all`, **not** Alembic; migration correctness must be verified against a real Postgres separately.
- The `client` fixture drops/creates all tables per test and calls `bootstrap_admin()` manually (httpx ASGITransport does not run lifespan).
- `pytest-asyncio` is in `asyncio_mode = "auto"` — async test functions need no markers.
- `login()` in conftest returns `(access_token, refresh_token)` — `recep, _ = await login(...)` then `auth(recep)`, **not** `recep[0]` (that's the first character of the token → 401).
- When testing a create endpoint, assert persisted fields on the **create response** — the multipart upload bug survived the whole suite because only post-PATCH values were checked.
- Repo-root `.env` (gitignored, real values) sets `BOOTSTRAP_ADMIN_*` — pydantic reads `env_file=".env"` **relative to CWD**, so behavior differs between running from repo root vs `backend/`. In tests this is masked by conftest env vars; be careful with manual scripts.
- **SQLAlchemy `Enum` columns persist the member NAME, not the value** (`users.role` was `'ADMIN'/'DOCTOR'/'RECEPTIONIST'` — uppercase). Any migration/script reading legacy enum columns as raw strings must match case-insensitively; this bit the roles backfill once (silently downgraded every user to receptionist — the fallback mapped unmapped rows). Migrations that transform data must fail loudly on unexpected values instead of defaulting.

## Environment / network gotchas

- PyPI/npm registries are unreliable here; mirrors are configured: PyPI via `https://package-mirror.liara.ir/repository/pypi/simple`, npm via `frontend/.npmrc` (Liara; if it 504s, retry with `--registry=https://mirror-npm.runflare.com`). `.npmrc`'s `allow-remote=all` is required — mirror metadata points at absolute Artifactory tarball URLs that npm 12 blocks otherwise.
- Docker Hub pulls: `docker-mirror.liara.ir` if direct pulls stall.
- **Docker bridge networking is broken in this dev sandbox** (veth `operation not supported`): use `--network host` for test containers, and `DOCKER_BUILDKIT=0 docker build --network=host` for image builds. The user's own compose stack runs fine elsewhere/on their kernel — don't "fix" the compose bridge network because a local test failed.
- The live compose stack (real patient data) runs on this machine: `new-patients-{db,api,web}-1`. The compose Postgres is mapped to host port **5434** (container name `db:5432`); a leftover test PG container on 5432 can masquerade as the real DB — check `docker ps` first. Credentials live in `.env` (never print/commit them). Feature changes are **not live until the images are rebuilt** (`docker compose up -d --build api web`) — a "missing" feature on the live UI is usually a stale container, not a code bug.
- **The live api container binds host port 8000** (and web port 80) — a local uvicorn on 8000 fails with "address already in use" that looks like a code bug. Run scratch dev backends on e.g. 8001 and point any static-server proxy there. Never run test mutations against the live stack (real patient data) — verify via its read-only endpoints (`/health`, image contents) only.
- `data/` is root-owned (from a volume mount); use `work/` for scratch files.
- For E2E/UI debugging: system chromium exists (`/usr/bin/chromium`, launch with `--no-sandbox` via playwright-core — a frontend devDependency since 1.3; `NODE_PATH=frontend/node_modules node script.cjs`). **The app uses `HashRouter`** — page URLs are `/#/patients/5`, so deep-link via the hash or click through the UI; plain `/patients/5` serves index.html at a route the router doesn't know. Vite dev server proxies `/api` to `:8000`; the compose nginx serves the same paths, so a local uvicorn + a tiny static server for `dist/` faithfully reproduces prod routing. Detach long-running dev servers with `setsid nohup ... < /dev/null & disown` — a plain background process dies with the shell's timeout. antd `AutoComplete` renders its placeholder as a span (`ant-select-selection-placeholder`), not an input attribute — locate its input via `input[role="combobox"]`, not `getByPlaceholder`.
- **Never `pkill`/`killall` (pattern-matched kills)**: they match any process whose command line contains the pattern — including your own shell (`pkill -f chromium` kills the shell running it) and unrelated user processes (orphaned E2E chromium, the live stack's uvicorn whose command contains `app.main:app` too). When you create a process and want to kill it later, capture its PID at launch (e.g. `echo $! > work/…/server.pid` or `pgrep -f <full-unique-pattern>` verified against the exact command) and kill only that PID. If precise targeting isn't possible, leave it running and ask the user to clean up.
- `page.waitForSelector('text=پراکسیس')` matches the **login page's own title** — wait for a post-login marker (e.g. the dashboard heading) or you'll race the async login and misread the app state.

## Architecture invariants

- **Permissions, not role hierarchy**: every endpoint checks `require_perm("...")` (any-of) from `app/api/deps.py`; the catalog + system-role permission sets live in `app/core/permissions.py` (mirrored inline in migration `d4e5f6a7b8c9`). `users.role_id` → `roles` (JSON `permissions_json`, partial-unique live name, soft-delete). System roles admin/doctor/receptionist are seeded idempotently by `bootstrap_admin()`; **the admin role is locked** (no edit/delete — lockout protection); other system roles editable but not deletable; custom roles refuse delete while users are assigned. Permissions are loaded per request (`selectinload(User.role)` is mandatory whenever a `User` is loaded and serialized — properties `role_name`/`permissions` read the relationship; a lazy load crashes async). `medical_notes.view` gates the cm/hx/px/rx blanking in the appointment serializer (server-side). `require_admin` ≡ `require_perm("users.manage")`; other admin perms: `roles.manage`, `audit.view`, `backup.manage`, `trash.purge`. **Adding a permission**: extend the catalog + the system-role sets in `permissions.py` (fresh installs get it via `bootstrap_admin`), AND have the new Alembic migration additively merge it into existing admin/doctor `permissions_json` (only `bootstrap_admin`-created rows update themselves — existing roles are pure data; migration `b1c2d3e4f5a6` does this for prescriptions).
- **Questionnaires** (branch `feature/questionnaires`): templates (`questionnaire_templates.format_json`) are validated JSON documents — pydantic `QuestionnaireFormat` in `app/services/questionnaires.py` (discriminated union: `number` with min/max/integer/unit, `choice` with 2–50 options each optional `score`, `string` with multiline/max_length; keys `^[a-z0-9_]{1,64}$` unique per template; optional `score_formula`; `extra="forbid"`). Every write path (API create/update, builder, **JSON upload**) funnels through the same validation; `POST /questionnaires/templates/validate` checks without saving. Responses belong to a **patient** (`questionnaire_responses.patient_id`, NOT appointment), multiple per template allowed, `answers_json` is raw nullable JSON. Server-side answer validation rejects unknown keys and type/range/choice violations only — **null/absent is always valid** (`required` is UI-level); 422s carry `details.fields` per-key errors, which the UI feeds back inline (`apiFieldErrors` → `form.setFields`), never just a toast. **No snapshot**: render merges stored answers with the *current* template (`frontend/src/lib/questionnaire.ts::mergeResponse`) — removed keys ignored, new questions null, invalid values "missing" + warning banner + confirm-dialog clear (PATCH re-validated). Access: `questionnaires.read`/`fill` (receptionist+ by default), `questionnaires.templates` (admin) for template CRUD.
- **Questionnaire scoring**: `score_formula` lives inside `format_json` (no migration). Parser/evaluator in `app/services/scoring.py` (tokenizer + recursive-descent AST — **never `eval`**; grammar: `+ - * /`, parens, numeric literals, question keys, `min`/`max` (1+ args), `abs` (1 arg); `FormulaError` becomes a 422 via the format validator). Refs must exist and be `number`/`choice` questions. `QuestionnaireFormat.score_of(answers)` evaluates per response and is **total**: any missing/invalid referenced answer, chosen option without a score, or division by zero → `None` (rendered as "—") — a score is never invented. The TS mirror (`validateFormulaText`/`evaluateFormula` in `frontend/src/lib/questionnaire.ts`) drives the builder's live check and rendering; without a formula the total falls back to the sum of chosen option scores. Keep parser semantics in sync between the two.
- **Responses report** (`/questionnaire-responses` page, menu gated by `questionnaires.read`): `GET /questionnaires/responses?template_id=` (`Page[QuestionnaireResponseReportOut]`, adds `patient_national_id`; multi-column select → **`paginate_rows`**, not `paginate`), subtree-filtered (live response + patient + template; deleted template → 404). Frontend table uses `scroll={{ x: 'max-content' }}` for many question columns; **CSV is generated client-side** (fetches all pages capped, UTF-8 BOM, quotes/escapes) so Excel renders Persian correctly. The fill form validates via antd rules from `questionRule()` (range/integer/choice/length, Persian messages) — do NOT reintroduce `InputNumber min/max/precision` props there (they *silently clamp* values, which is the "validation doesn't work" bug).
- **Prescriptions** (v1.3): structured replacement for the legacy free-text `appointments.rx` (the column is KEPT as a deprecated, never-written archive — still blanked without `medical_notes.view`, shown read-only behind «نسخه قدیمی»). Tables: `prescriptions` (belongs to a **PATIENT**, like questionnaire responses; `prescribed_at`, `notes`, `created_by_id`, `source_appointment_id` = provenance of a migrated prescription, intentionally NO FK), `prescription_items` (tag-like dictionary — partial-unique live name, soft delete, powers the autocomplete), `prescription_item_links` (prescription+item pair, unique, optional `quantity`; editing a prescription REPLACES its links). Create/update with an unknown item **name** auto-registers it (case-insensitive match first) — no separate taxonomy perm; dictionary rename/delete via `prescriptions.write`. Access: `prescriptions.read`/`prescriptions.write` — doctor+ by default, receptionist none (medical data, consistent with `medical_notes.view`). The legacy rx → prescriptions conversion lives in `app/services/rx_migration.py` — a **frozen** parser shared by the Alembic migration AND `scripts/migrate_sqlite.py`; its rules (split on comma/newline, Persian digits normalized, trailing standalone integer = quantity, dictionary admission only for names seen ≥ 3× corpus-wide, verbatim overflow into notes) must not change — historical data was converted with them and the unit tests pin them down. Item rows use antd `AutoComplete` + `Form.List`; quantity validates via a rule (Persian message), NOT `InputNumber` min-clamping (same clamp bug pattern as the questionnaire answer inputs).
- **Soft deletes everywhere**: domain tables + `users` + `roles` + questionnaire + prescription tables have `deleted_at`; uniqueness is via **partial unique indexes** (`uq_*_live`, `WHERE deleted_at IS NULL`) so deleted values are reusable. Read paths must filter `deleted_at IS NULL` across the whole parent chain (a file is visible only if itself + its patient are alive — files are patient-level since 1.3) — the trash API (`app/api/v1/trash.py`) implements list/restore (perm `trash.view`/`trash.restore`) and purge (perm `trash.purge`, the only path that unlinks physical files). Covers patients/appointments/transactions/attachments/tags/diagnoses/users/roles/questionnaire_templates/questionnaire_responses/prescriptions/prescription_items; subtree rule: a child refuses restore (409 `parent_still_deleted`) while its parent is deleted (attachment/prescription/questionnaire-response parent = patient; transaction parent = appointment). Never hard-delete in regular endpoints; never unlink files on soft delete.
- **Audit trail**: every mutating endpoint calls `services/audit.py::log_action` (never raises) before returning; admin-only listing `GET /admin/audit`. New mutations must be audited.
- **Session lifecycle**: login is throttled — after `LOGIN_MAX_FAILURES` failed logins for one username within `LOGIN_LOCK_MINUTES`, `/auth/login` returns 429 `login_locked` (window-based, state in `login_audit`, **per-username only** — behind nginx every request shares the proxy IP, so per-IP counting would let one attacker lock out everyone). Unknown usernames verify a dummy argon2 hash (no timing-based username enumeration). Refresh tokens rotate on every `/auth/refresh`; `PATCH /users/{id}` with a new password (or `is_active: false`) and user deletion revoke that user's outstanding refresh tokens; `POST /auth/logout` revokes the presented token and is audited (action `logout`, entity `session`). Access tokens stay valid up to their 30-min TTL after logout — accepted (per-request `is_active`/`deleted_at` is the revocation path; there is **no** TokenCache — don't reintroduce one). See docs/auth.md.
- **Attachments** (patient-level since 1.3 — `attachments.patient_id`; they survive appointment deletion; migration `b1c2d3e4f5a6` re-parented legacy rows): two kinds of rows — real files (`stored_filename` set) and **note-only** rows (`stored_filename IS NULL`, `original_filename IS NULL`, `missing_file=False`; created via `POST /patients/{id}/files/note`, doctor+). `missing_file=True` means "a file was expected but is absent" (migration), NOT note-only. Download must handle both. The partial unique index `uq_attachments_stored_filename_live` tolerates multiple NULLs (SQLite + PG), so note-only rows never collide. `scripts/check_files.py` skips `stored_filename IS NULL`. Attaching/replacing content: `POST /files/{id}/content` (multipart `file`, perm `files.write`) — sets/replaces `stored_filename`/`original_filename`/`mime_type`/`size_bytes`, clears `missing_file`, preserves description/notes, audited; **the superseded physical file stays on disk** (trash purge remains the only unlink path — replaced files become orphaned by design). `AttachmentOut.stored_filename` is exposed as the UI's content-identity signal (preview refetch key). Uploads are **streamed** (`deps.py::save_upload_stream`, 1 MiB chunks) with `MAX_UPLOAD_BYTES` enforced mid-read — never `await file.read()` a whole upload into memory, and no partial file may survive a rejection. List/upload are patient-scoped (`GET/POST /patients/{id}/files`); there are NO appointment-scoped file routes anymore and `AppointmentBrief` no longer carries `attachment_count`.
- **Transactions/payments**: cash-vs-card is the `pos` bool (کارت‌خوان/نقدی). Day-wide payments view: `GET /payments?date=` (payments.py; APP_TZ day boundaries on the **appointment's** `scheduled_at`, defaults to today-in-Tehran, receptionist+; `Transaction` has no created_at, so the appointment date is the payment timestamp). Per-type aggregates for the same day: `GET /payments/summary?date=` (`PaymentTypeStat`: count/total/POS/cash split).
- **Taxonomies (tags/diagnoses)**: Persian alphabetical order lives in the DB — production `name` columns carry an ICU `fa` collation (`fa_sort`, migration `f9e8d7c6b5a4`, deterministic → uniqueness unaffected; SQLite dev stays BINARY), so `ORDER BY name` needs no app-side sorting; `Patient.tags`/`.diagnoses` relationships have `order_by=` name. Renaming onto an existing live name: 409 `name_taken` unless `?merge=true` — merge moves M2M links to the survivor (dedupe against the composite PK first), soft-deletes the source (trash-restorable), one transaction, audited as `merge`; requires the same `taxonomies.write` that gates deletion.
- **Backup** (`app/api/v1/backup.py`, `backup.manage`, audited): on-demand job — `POST /admin/backup` starts a daemon thread (module-level status dict + lock; 409 `backup_running` if concurrent), `GET` polls status/size, `GET /download` streams the tar.gz (manifest **v3**: `schema_version`/`app_version`/`table_columns` + DB dump + `uploads/`; dot-dirs excluded), `DELETE` discards. The api container has **no pg_dump** — the DB is dumped via psycopg2 `COPY ... TO STDOUT` per table (FK order in `DUMP_TABLES` — keep new tables in FK-safe order: roles before users, questionnaire_templates before questionnaire_responses, prescription_items before prescriptions/links, patients before prescriptions — REPEATABLE READ snapshot); `_psycopg2_url()` must strip dialect schemes (`postgresql+asyncpg://` → plain `postgresql://` — raw psycopg2 cannot parse `+psycopg2`/`+asyncpg` DSNs). Table dumps use `SpooledTemporaryFile` and uploads are streamed — never buffer the archive in memory. **Import** (`POST /admin/backup/import`, same lock via `services/backup_state.py::JOB_LOCK`): tarball pre-validated (member allowlist, zip-slip guards); version rules — older app_version imports via manifest column lists (only dumped tables replaced — a partial dump must SKIP absent `db/<table>.copy` members, not `getmember` them: that KeyError regression crashed the PG path once; missing columns filled from DDL default, else type-aware `''`/`0`; unknown dump columns dropped; skew reported in summary). **Pre-1.3 backups (schema_version ≤ 2)**: attachments arrive with `appointment_id` → remapped to `patient_id` via the dumped appointments (dangling → loud rollback); `TRUNCATE … CASCADE` on patients also wipes prescriptions (absent from old dumps), so they are **re-derived from the restored rx text** in the same transaction (`_rederived_from_rx` in the summary). Note: CASCADE also clears other FK dependents of dumped tables (transactions, questionnaire_responses, …) — harmless for full dumps, by-design data replacement for partial ones. Newer app_version → 409 `newer_version` unless `force=true`; the whole DB import is one transaction (PG: TRUNCATE+COPY+setval; SQLite: ATTACH+INSERT…SELECT) — any error rolls back. uploads/ extracted via `.import-*` staging inside UPLOAD_DIR, moved after commit. **Uploads purge** (`services/uploads_purge.py`): automatic (startup + every 6h) — unlinks storage-named files referenced by no attachment row (live or deleted), 24h mtime grace, hidden dirs skipped, audited as `system`; foreign files never touched.
- **Alembic**: `alembic/env.py` converts the async URL (asyncpg→psycopg2), so `psycopg2-binary` is a required dep. **The app migrates at startup** (`app/db/migrations.py::run_migrations`, called fail-fast from the lifespan BEFORE `bootstrap_admin` — any launch path; on failure the app refuses to boot). `create_all`-built databases without `alembic_version` (dev/CI) are stamped at head, never re-migrated; fresh empty SQLite is create_all+stamp (the chain is partially SQLite-incompatible); fresh PostgreSQL runs the real chain. **Snapshot before deploying migrations or purging** (`scripts/snapshot_db.py`; rollback = `pg_restore --clean --if-exists`, see the script docstring). Migrations are additive and must be safe to auto-apply on a live DB at boot.
- **Pagination**: `Page[T]` + `paginate()` (single-column selects) / `paginate_rows()` (multi-column selects — `db.scalars` silently drops extra columns).

## Conventions

- **Commit messages are brief — a single-line summary, nothing else** (no body). Details belong in code comments, docs, or the version history in `backend/app/__init__.py`, not the commit message.

- API errors use the uniform envelope `{"error": {"code", "message", "details"}}` via `app/core/errors.py` (`ConflictError` 409, `BusinessRuleError`/validation 422, `NotFoundError` 404, `RateLimitedError` 429). Raise these instead of bare `HTTPException` where a code matters.
- **FastAPI multipart**: fields alongside an `UploadFile` must be declared with `Form("...")` — a bare `param: str = ""` becomes a *query param* and the form field is silently dropped (this exact bug shipped once: upload description/notes never persisted).
- UI is Persian/RTL with Jalali dates: internal state and API contract stay **Gregorian ISO/UTC**; only display/input is Jalali. Pickers: `frontend/src/components/JalaliDates.tsx` (react-multi-date-picker); display helpers: `src/lib/jalali.ts` (incl. `toFaDigits`/`toEnDigits` — normalize Persian-digit *input* with `toEnDigits` before sending; the DB stores ASCII digits). Backend day-boundary logic uses `APP_TZ` (Asia/Tehran) from `app/db/session.py`; day-based pages (dashboard/schedule/payments) take their initial date from `GET /meta/today` via `lib/today.ts::serverToday()` — never `new Date().toISOString()` (UTC ≠ Tehran between 20:30–24:00 UTC).
- antd Select with `options=[{value: id, label: name}]` needs `showSearch` + `optionFilterProp="label"` — the default filter matches against `value` (the numeric id), so searchable selects silently show "no results" without it. Modal forms whose values must not survive a reopen should reset on open (form instance lives outside the modal); prefer `destroyOnHidden` (antd ≥5.25, `destroyOnClose` is deprecated).
- **Modals are mask-closable=false** — dialogs close only via their buttons (outside clicks must not dismiss; Esc may). Every `<Modal>` carries `maskClosable={false}`; keep that on new ones.
- **Unsaved-changes guard** (patient page): the `Segmented` view switch and appointment selection route through `requestNav` → a 3-button confirm (ذخیره و ادامه / دورریختن تغییرات / بازگشت) when the appointment-notes form (`AppointmentPanel` reports dirty via `onDirtyChange`, imperative `ref` handle `isDirty/save/reset`), the questionnaire form (parent watches `qForm`), or the prescription form (parent watches `rxForm` — create seeded via a `seed` prop, applied after reset) is dirty. **Route-level**: sidebar-menu navigations go through `navigateGuarded` (`components/NavGuard.tsx`) — the mounted page registers a `NavBlocker` (isDirty/requestLeave) and opens the same dialog with a `{kind:'route', to}` pending-nav; tab close/refresh uses `useBeforeUnloadGuard(dirty)` (native dialog). Guard-initiated saves complete the navigation through `afterSaveRef` (cleared on save failure; saveActiveForm picks the dirty form by priority rx → q → appt). **`AppointmentPanel` must be mounted with `key={appointmentId}`** — rc-field-form does not re-apply `initialValues` on re-render, so without the remount the previous appointment's CM/HX/PX stay in the form (overwrites the wrong appointment's notes on save).
- **Files UI** (patient-level since 1.3): patient «همه فایل‌ها» view = sidebar list (no expandable rows; row click selects; «افزودن فایل» opens the upload modal — description + optional file, note-only when no file) + `FileDetailPane` (title/شرح/date/size, notes edit via `FileNotesExpanded`, download via `lib/files.ts::downloadAttachment` — the authorized axios-blob helper; attach/replace content via the `Upload` button → `POST /files/{id}/content`; image/PDF preview fetched as a blob → object URL, revoked on change/unmount, refetched when `stored_filename` changes; in-page image zoom toolbar). The appointment panel has NO files tab anymore (files live on the patient page). Attachments never render from bare URLs — the download endpoint needs the `Authorization` header.
- **Versioning**: `backend/app/__init__.py::__version__` (single source for the API, exposed by `GET /health`) and `frontend/package.json` `version` (single source for the UI, injected as `__APP_VERSION__` via vite `define`, shown next to the header title). Bump both together (semantics: minor for features, patch for fixes) and record the change in the `__init__.py` history.
- **Tests must derive «today» from `APP_TZ`** (`tests/test_payments.py::_today`) — UTC and Tehran dates differ between ~20:30–00:00 UTC, which made payment tests fail at night (the API defaults to today-in-Tehran).
- Dark mode: `useTheme()` from `frontend/src/components/ThemeContext.tsx` (persisted `clinic-theme` localStorage, `html.dark` class, switches antd `theme.darkAlgorithm`). Derive custom colors from `theme.useToken()` tokens (e.g. `colorBgContainer`) — never hardcode `#fff`/`#eee` in components. Jalali picker inputs are themed via CSS overrides in `index.css` (their inline style can't be overridden by class).
- ruff line-length 100; `B008` ignored (FastAPI `Depends()` defaults). mypy must stay clean — annotate `dict[str, Any]` for dict-literal params, and don't unpack into `_` inside endpoints that already have the `_` User dependency (mypy: "variable has type User").
- File uploads from the UI go through the axios client (`api.post` with `FormData`; antd `Upload` only selects the file via `beforeUpload: () => false`) — never antd's auto-XHR upload path, which bypasses the token-refresh interceptor. Same for the questionnaire **JSON upload**: parse with `File.text()` + `JSON.parse` in the browser, POST to `/questionnaires/templates/validate`, then load into the builder — never submit raw files to the API.
- Frontend permission checks: `hasPerm()` from `useUser()` (AppLayout context; permissions come from login → `/auth/me` → localStorage). Never check `user.role_name` for access decisions in the UI — roles are data now. The frontend can hide actions, but the server is authoritative (`require_perm`).
- Legacy import tooling: `scripts/migrate_sqlite.py` (dry-run default, `--apply` idempotent, content-hash dedup for files; legacy English payment descriptions `Visit`/`Spiro`/`Other` are translated to ویزیت/اسپیرو/سایر via `normalize_txn_description` — case-insensitive after strip, unmatched values kept as-is; since 1.3 attachments resolve to the PATIENT via the legacy appointment (halts on dangling refs) and legacy rx text converts to structured prescriptions via the frozen `app/services/rx_migration.py` parser — prescriptions dedupe on `source_appointment_id`), `scripts/check_files.py` (DB↔disk consistency), `scripts/verify_import.py` (independent cross-check; its DB DSN is hardcoded to a test container; also checks the rx→prescriptions conversion). `old_database/` is a real production snapshot — treat as sensitive.
