# لاگ اقدامات

هر عمل تغییردهنده (ایجاد / ویرایش / حذف / بازیابی / پاک‌سازی) پیش از
بازگشت اندپوینت در جدول `audit_log` ثبت می‌شود:

- کاربرِ عامل (یا `system` برای نگهداشت خودکار، مثل پاک‌سازی uploads)،
  مهر زمانی (timestamptz)، عمل، نوع و شناسهٔ موجودیت
- خلاصهٔ خوانا — مثلاً «نام نام‌خانوادگی (کد ملی)»، «قدیمی → جدید» برای
  تغییر نام، «ویزیت — 1500000» برای پرداخت‌ها (اول شرح، سپس مبلغ خام)
- payload جی‌سانیِ `details` با تفاوت‌های سطح فیلد (نام قدیمی/جدید، خلاصهٔ
  واردسازی پشتیبان، شمار پاک‌سازی…)
- IP کلاینت — نخستین هاپِ `X-Forwarded-For` (کلاینتِ اصلی پشت پروکسی
  nginx)، در نبودش `X-Real-IP`، و در دسترسی مستقیم آدرس همتا

تلاش‌های ورود در جدول جداگانهٔ `login_audit` نگه‌داری می‌شود؛ پایان نشست
(خروج) با اکشن `logout` و موجودیت `session` ثبت می‌شود.

## مشاهده

- صفحهٔ ویژهٔ مدیر `/audit` (دسترسی `audit.view`) با فیلتر عمل/موجودیت.
- API: `GET /admin/audit?entity_type=...` (صفحه‌بندی‌شده).

## قراردادها

- `log_action` **هرگز خطا نمی‌دهد** — لاگ‌گرفتن نباید درخواست را بشکند.
- اندپوینت‌های تغییردهندهٔ جدید باید آن را صدا بزنند؛ `details` باید برای
  بازسازیِ «چه چیزی عوض شد» کافی باشد (در خروجی API رشتهٔ JSON است).
