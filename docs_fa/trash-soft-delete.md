# حذف نرم و سبد بازیافت

## معنا

- همهٔ حذف‌ها **نرم** است (`deleted_at`) — جداول دامنه، کاربران، نقش‌ها و
  جداول پرسش‌نامه alike.
- یکتایی (کد ملی، نام برچسب/تشخیص/کاربر/نقش/قالب) فقط بین ردیف‌های زنده با
  **ایندکس یکتای جزئی** (`WHERE deleted_at IS NULL`) تضمین می‌شود؛ مقدار
  حذف‌شده قابل استفادهٔ مجدد است و بازیابی فقط با وجود هم‌نام زنده تعارض
  می‌گیرد (409).
- اندپوینت‌های معمولی هرگز سخت حذف نمی‌کنند و هرگز فایل فیزیکی را unlink
  نمی‌کنند.
- نماهای خواندن `deleted_at IS NULL` را در کل زنجیرهٔ والد اعمال می‌کنند —
  فایل فقط وقتی دیده می‌شود که خودش + نوبت + بیمار زنده باشند.

## API سبد بازیافت (`app/api/v1/trash.py`)

| عمل | اندپوینت | دسترسی |
| --- | --- | --- |
| فهرست حذف‌شده‌ها | `GET /admin/trash/{type}` | `trash.view` |
| بازیابی | `POST /admin/trash/{type}/{id}/restore` | `trash.restore` |
| پاک‌سازی همیشگی | `DELETE /admin/trash/{type}/{id}` | `trash.purge` |

- **قاعدهٔ زیرشاخه**: فرزند در حالی که والد حذف است، بازیابی را رد می‌کند
  (409 `parent_still_deleted`)؛ بازیابی والد زیرشاخه را برمی‌گرداند.
- **پاک‌سازی** تنها عملی است که فایل فیزیکی را unlink می‌کند — بازگشتی ندارد.
- انواع پوشش‌داده‌شده: patients، appointments، transactions، attachments،
  tags، diagnoses، users، roles، questionnaire_templates،
  questionnaire_responses.

## مرتبط: پاک‌سازی خودکار uploads

فایل‌های دیسک که به هیچ ردیف پیوستی اشاره نمی‌کنند به‌صورت خودکار جمع
می‌شوند — بخش «پاک‌سازی uploads» در backup-import.md را ببینید.
