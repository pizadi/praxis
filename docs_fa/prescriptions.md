# نسخه‌ها (v1.3)

جایگزین ساختاریافتهٔ فیلد متنیِ قدیمی `appointments.rx`.

## مدل داده

- `prescriptions` — به **بیمار** تعلق دارد (مثل پاسخ پرسش‌نامه‌ها)؛
  `prescribed_at` (زمان تجویز)، `notes`، `created_by_id` (کاربر)، حذف نرم.
  `source_appointment_id` ثبت می‌کند نسخه از کدام نوبت مهاجرت کرده است
  (فقط پیشینه — بدون FK).
- `prescription_items` — فرهنگِ شبیه برچسب/تشخیص (یک دارو، آزمایش،
  دستورالعمل)؛ نام‌های زنده یکتا (ایندکس جزئی)؛ حذف نرم؛ منبع
  پیشنهادِ خودکار.
- `prescription_item_links` — (نسخه، قلم) + `quantity` (NULL = بدون تعداد /
  میراثی). جفتِ یکتا برای هر نسخه؛ ویرایش نسخه، اقلامش را از نو می‌سازد.

## تبدیل نسخه‌های متنی قدیمی (قواعد ثابت — `app/services/rx_migration.py`)

مهاجرت ۱٫۳ (و `scripts/migrate_sqlite.py` برای واردات تازه) متنِ rx هر نوبت
را به یک نسخه تبدیل کرد:

- اقلام با کاما/خط جدید جدا می‌شوند؛ ارقام فارسی نرمال می‌شوند؛
- آخرین عددِ مستقلِ سطر → تعداد (`P1 20` → P1 × ۲۰؛ `MTX 15` → MTX × ۱۵ —
  ابهامِ دوز/تعداد از پیش پذیرفته شده است)؛
- کلید یکسان‌سازی نام: حروف کوچک، فاصله‌های فشرده، نقطه‌گذاریِ لبه‌ها؛
  پرتکرارترین املای هر نام، نام نمایشی می‌شود؛
- فقط نام‌های **≥ ۳ بار در کل داده** وارد فرهنگ شدند (حدود ۸۰۰ قلم از
  داده‌های قدیمی، پوشش ~۸۵٪)؛ بقیه (جمله‌های یک‌بارمصرف مثل
  «i should see ct…»، غلط‌های املایی) **عیناً در یادداشت نسخه** حفظ شدند؛
- متن اصلی هم در ستون منسوخ‌شدهٔ `appointments.rx` باقی است (دیگر توسط
  برنامه نوشته نمی‌شود؛ بدون `medical_notes.view` سمت سرور خالی می‌شود؛ در
  UI پشت «نسخه قدیمی» فقط-خواندنی دیده می‌شود).

این قواعد **ثابت** هستند — مهاجرت Alembic و اسکریپت واردات هر دو از یک
پارسر مشترک استفاده می‌کنند و تست‌ها آن را قفل کرده‌اند. تغییرشان یعنی
بازنویسی متفاوتِ تاریخچه در نصب‌های مختلف.

## اندپوینت‌ها

| عمل | اندپوینت | دسترسی |
| --- | --- | --- |
| جستجوی فرهنگ (پیشنهاد خودکار) | `GET /prescription-items?q=` | `prescriptions.read` |
| تغییر نام قلم (اصلاح غلط) | `PATCH /prescription-items/{id}` | `prescriptions.write` |
| حذف نرم قلم فرهنگ | `DELETE /prescription-items/{id}` | `prescriptions.write` |
| فهرست نسخه‌های بیمار | `GET /patients/{id}/prescriptions` | `prescriptions.read` |
| ثبت نسخه | `POST /patients/{id}/prescriptions` | `prescriptions.write` |
| مشاهده یک نسخه | `GET /prescriptions/{id}` | `prescriptions.read` |
| ویرایش (در صورت ارسال، اقلام از نو ساخته می‌شوند) | `PATCH /prescriptions/{id}` | `prescriptions.write` |
| حذف نرم | `DELETE /prescriptions/{id}` | `prescriptions.write` |

- ثبت/ویرایش با نام قلمِ جدید آن را خودکار وارد فرهنگ می‌کند (اول تطبیق
  نام-به-کوچک/بزرگ حروف) — دسترسی جداگانه‌ای نمی‌خواهد؛ پزشکِ نسخه‌نویس
  واژگان را رشد می‌دهد.
- هر نوشتن در لاگ اقدامات ثبت می‌شود؛ نسخه‌ها از سبد بازیافت بازمی‌گردند
  (والد = بیمار).

## دسترسی‌ها

`prescriptions.read` / `prescriptions.write` (گروه جدید «نسخ‌ها» در صفحهٔ
نقش‌ها). پیش‌فرض: پزشک = خواندن+نوشتن، پذیرش = هیچ (نسخه دادهٔ پزشکی است —
همسو با `medical_notes.view`)، مدیر = همه. مهاجرت ۱٫۳ این دو دسترسی را
جمعی (بدون حذف) به نقش‌های فعلی admin/doctor می‌افزاید.

## رابط کاربری

- صفحهٔ بیمار → «نسخه‌ها» (نمای چهارم فهرست کناری): فهرست + مشاهده/ویرایش/ثبت؛
  اقلام به‌صورت چیپ (`نام × تعداد`).
- پنل نوبت → تب «نسخه‌ها»: نسخه‌های بیمار با دکمهٔ ثبت سریع که زمان نوبت را
  پیش‌فرض می‌گذارد؛ نسخهٔ متنی قدیمیِ نوبت‌های قدیمی در تب «یادداشت‌ها»
  فقط-خواندنی دیده می‌شود («نسخه قدیمی»).
- فرم ثبت: تایپ نام قلم → پیشنهاد از فرهنگ (جستجوی سمت سرور با تأخیر)؛
  نام جدید هنگام ذخیره خودکار ثبت می‌شود. فیلد تعداد مقدار را بی‌صدا
  گیر نمی‌کند (به‌جای clamp شدن، پیام اعتبارسنجی فارسی دارد — الگوی باگِ
  min/precision اینپوت‌نامبر).
